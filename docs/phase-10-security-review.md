# Phase 10 security review

Review date: 2026-08-04. Scope: desktop OAuth and credential brokering, provider adapters and remote input, synchronization documents/assets, and the content-free notification relay. This review is a release gate and must be repeated after a protocol, scope, credential-storage, relay-authentication, or remote-schema change.

## Trust boundaries and conclusions

| Boundary                          | Controls and automated evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Residual risk / operator gate                                                                                                                                              |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| System browser to Electron        | Authorization Code with PKCE, loopback-only callback, one-time state and nonce validation, bounded timeout/cancellation, issuer/signature/account checks. Electron auth tests cover success, mismatch, cancellation, refresh, revocation, and reconnect.                                                                                                                                                                                                                                                                         | Production Google and Microsoft registrations, consent-screen verification, and packaged callbacks must be exercised with release client IDs.                              |
| Electron to OS credential storage | Refresh credentials are Electron-owned and encrypted through `safeStorage`; plaintext fallback is rejected. The renderer receives public account state only. Packaged verification checks encrypted persistence on two isolated instances.                                                                                                                                                                                                                                                                                       | Verify the signed installer on every supported Windows version and user profile. Compromised user sessions or OS credential stores remain outside the app threat boundary. |
| Backend credential broker         | Random loopback authorization, bounded JSON, provider/request validation, replayed request-ID rejection, short-lived access tokens, and redacted errors. Bootstrap data is inherited privately and never placed on the command line.                                                                                                                                                                                                                                                                                             | A process running as the same user may inspect process memory; keep broker lifetimes and access-token TTLs bounded.                                                        |
| Provider remote input             | Versioned schemas, logical-key/entity relationships, canonical hashes, MIME/hash/size validation, conditional versions, quarantine, safe cursor invalidation, and repair paths prevent unverified overwrite. Authenticated Graph continuations and preauthenticated upload-session targets are restricted to trusted HTTPS Microsoft endpoints before requests or asset bytes are sent. Adapter tests cover corrupt input, pagination, hostile continuation/upload URLs, throttling, invalid cursors, and interrupted transfers. | Provider API behavior and quotas can change. Staging must run both shared adapter contracts and real-account smoke tests before activation.                                |
| Relay registration and routing    | Opaque high-entropy route IDs, HMAC challenge proof, single-use challenges, short-lived bearer tokens, secret versions with bounded rollover, authenticated WebSockets, hashed channel tokens, monotonic Google message numbers, workspace-scoped Durable Objects, and fixed content-free broadcasts.                                                                                                                                                                                                                            | Route IDs are bootstrap capabilities. TLS, WAF limits, Durable Object isolation, and secret access must be verified in the deployed Cloudflare account.                    |
| Replay and abuse protection       | One-time challenges, token expiry/use limits, message-number deduplication, body/frame/connection limits, workspace and IP rate windows, coalescing, and backpressure closure. Relay tests cover spoof, replay, duplicate, burst, oversized, isolation, and renewal ownership.                                                                                                                                                                                                                                                   | Distributed attacks are also constrained by Cloudflare WAF/rate limiting; alerts must be active before production traffic.                                                 |
| Secret rotation                   | Relay accepts exactly the next secret version, bounds previous-verifier overlap to 24 hours, and closes old-version sockets after rollover. Raw notification keys never leave desktops.                                                                                                                                                                                                                                                                                                                                          | Exercise rotation and reconnect in staging; record the operator and completion time. Do not extend rollover to recover a broken deployment.                                |
| Logs and diagnostics              | Backend/Electron errors are allowlisted or redacted; relay structured logs contain only event, outcome, code, duration, and count. Invocation logs are disabled because URLs contain opaque route IDs. No synchronized content, headers, bodies, account IDs, tokens, proofs, or provider resource IDs are logged.                                                                                                                                                                                                               | Restrict Cloudflare Logs/Logpush access and enforce seven-day deletion. Release diagnostics must be reviewed before sharing externally.                                    |

## Security verification commands

Run from the repository root:

```powershell
npm run test
npm run lint
npm run verify:phase-10
npm run verify:phase-10:package
```

The package gate launches two isolated packaged processes concurrently. Each process verifies Google Drive and OneDrive PKCE exchange behavior, signed ID-token validation, encrypted refresh-token persistence, authenticated broker access, and disconnect cleanup without using production credentials.

## Release-blocking findings

Activation is blocked if any automated gate fails; broad Microsoft drive scopes are registered; a Microsoft client secret is embedded or the extractable Google Desktop credential is exposed outside the build artifact and Google token endpoint; `safeStorage` encryption is unavailable; relay logs contain route/device identifiers or request data; remote corruption advances a cursor as successfully applied; provider/relay outage loses a local outbox mutation; or staging cannot demonstrate workspace isolation, replay rejection, rotation, and fallback reconciliation.

The relay is an availability optimization, not a correctness authority. Provider cursors and local outbox state remain authoritative, so relay loss must never authorize rollback, deletion, or cursor advancement.
